# Basketball controls and presentation

Pick up the owned room's loose ball with E / USE. Hold Space or the mobile SHOOT button to begin a jump shot. Alternatively, press and hold on the court with the mouse or a finger. Drag left/right to change the landing aim; drag up/down to raise/lower the arc. Release the shooting key/button or the original court pointer to launch. A second finger can adjust the arc while holding SHOOT. A secondary drag while holding Space changes aim without firing until Space is released. Q / DROP returns a held ball to clear floor space.

The yellow trajectory arc is rendered at 75% opacity and uses the same launch position, gravity, landing aim and timing error as the actual flight. It ends at the rim or marks the first backboard contact. Players judge release timing from the jump animation and arc; there is no release bar or aiming instruction overlay. The ideal release is 0.62 seconds after the jump starts, with a perfect window of +/- 0.012 seconds. Early/late shots drift and lose quality. Holding beyond 1.08 seconds automatically releases. Aim and release timing both matter; a perfect release can still miss if aimed away from the opening. The separate ball retains its original 24-world-pixel diameter; collision uses the same 12-pixel radius.

There are twelve generated gather/rise/apex poses and four generated release/landing poses per authored view. Five authored directions and the established three horizontal mirrors cover all eight directions. Dribble frames advance from actual travel distance when moving. The standing scale matches the configured player body height, and every frame shares a shoe anchor with clear transparent gutters. The ball is a separate sprite, so rabbit fur and overalls use the normal customization shader while the ball stays orange.

The measured backboard face is positioned relative to the current portable goal in `breakroom_games.lua`. The rim projects in front of that face: foreground screen overlap is rendered in front, while a ball entering the board plane collides. Movement is swept by distance and first contact is bisected to prevent tunneling during slow frames. Board rebounds reflect the incoming velocity and fall back to retrievable floor space. Flights render above the elevated goal instead of being hidden by ground-y sorting.

LAN protocol 36 carries validated final aim and sampled release time on the reliable release request. The host owns possession, collision and scoring. Each bay's live ball is sent as a separate bounded snapshot shard; clients merge by bay and reject older ball ticks. This keeps both rooms' balls within the existing 1,200-byte motion packet limit. Live shots and aim are transient; saving retains the last placed ball position.

## Generated assets and reproducibility

Built-in imagegen produced the five new transparent reference atlases. Immutable originals and the exact prompts are in `assets/source/basketball-actions-v2/`, named `north`, `northeast`, `east`, `southeast`, and `south` (`.png` and `-prompt.txt`). The prompts request the existing rabbit identity, a 4-column / 6-row atlas, eight dribble poses and sixteen distinct shot poses, clear gutters, and no embedded basketballs.

`tools/build_basketball_actions.py` locates complete disconnected poses before cropping, preserves generated RGBA, rescales and packs them into 256-pixel cells. This avoids cutting ears at approximate generated row boundaries. It never paints or alters pose anatomy. It writes the five matching runtime PNGs and `manifest.json` to `assets/generated/basketball-actions-v2/`. The normalized atlas is 1024 x 1536, with foot anchor (128, 240) and standing reference height 196. The game scales that reference to the normal configured player height.

Contact sheets and in-engine captures are available in `output/basketball-v2/`. Rebuild with the project's Python runtime and Pillow/numpy; run the focused LÖVE tests with `PICTURE_SHOP_SMOKE_FOCUS=basketball`. Set `PICTURE_SHOP_BASKETBALL_CAPTURE_DIR` to an existing output directory to save customized dribble, apex aiming, flight layering and backboard-contact captures. Test saves use an isolated disposable identity.
